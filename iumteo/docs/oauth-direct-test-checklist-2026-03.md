# 네이버·구글 로그인 직접 테스트 체크리스트

작성일: 2026-03-13

## 1. 목적

이 문서는 양양이음터의 네이버 로그인과 구글 로그인이 실제 브라우저에서 정상 작동하는지 대표가 직접 검증하기 위한 체크리스트다.

이번 테스트의 핵심은 아래 4단계가 되는지 확인하는 것이다.

1. 로그인 버튼 클릭
2. 네이버 또는 구글 인증 화면 이동
3. 인증 완료 후 우리 사이트로 복귀
4. `/register` 화면에서 세션이 살아 있는지 확인

## 2. 테스트 전 필수 확인

### 2.1 `.env.local`

`iumteo/.env.local`에 아래 값이 실제로 들어 있어야 한다.

- `NEXTAUTH_URL=http://localhost:3000`
- `NEXTAUTH_SECRET=충분히 긴 랜덤 문자열`
- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `NAVER_CLIENT_ID`
- `NAVER_CLIENT_SECRET`

## 2.2 OAuth 콘솔의 콜백 URL

### 구글

아래 URL이 등록되어 있어야 한다.

- `http://localhost:3000/api/auth/callback/google`

배포 테스트도 할 예정이면 배포 도메인용 콜백 URL도 추가해야 한다.

### 네이버

아래 URL이 등록되어 있어야 한다.

- `http://localhost:3000/api/auth/callback/naver`

배포 테스트도 할 예정이면 배포 도메인용 콜백 URL도 추가해야 한다.

## 2.3 개발 서버 실행

로컬에서 아래 명령이 실행되어야 한다.

```powershell
npm run dev
```

접속 URL:

- `http://localhost:3000/login`

만약 실행이 안 되면 먼저 아래를 확인한다.

- `iumteo/node_modules`가 정상 설치되었는지
- `next` 명령이 실행 가능한지
- 터미널 위치가 `iumteo` 폴더인지

## 3. 구글 로그인 직접 테스트

### 테스트 순서

1. 브라우저에서 `http://localhost:3000/login` 접속
2. `구글 계정으로 가입/로그인` 버튼 클릭
3. 구글 로그인/동의 화면이 뜨는지 확인
4. 로그인 완료 후 우리 사이트로 복귀하는지 확인
5. 복귀 위치가 `/register`인지 확인
6. `/register` 화면에서 이름/이메일이 자동 입력되는지 확인

### 기대 결과

- 구글 인증 화면으로 이동한다.
- 인증 후 `http://localhost:3000/register`로 돌아온다.
- 이름 또는 이메일 중 최소 이메일은 자동으로 채워진다.
- 오류 없이 폼 입력이 가능하다.

6. `/register` 화면에서 이름/이메일이 자동 입력되는지 확인

### 기대 결과

- 네이버 인증 화면으로 이동한다.

## 5. 세션 확인 테스트

소셜 로그인 성공 후 아래도 확인한다.

1. `/register` 화면에서 새로고침
2. 이름/이메일 자동 입력 상태가 유지되는지 확인
3. 가입을 진행하지 않고 `/login`으로 다시 이동
4. 필요하면 `/admin`, `/profile`, `/teacher` 접근 시 어떤 화면으로 가는지 확인

기대 결과:

- 새로고침 후에도 세션이 유지된다.
- 권한이 아직 없는 경우에는 가입 유도 흐름으로 간다.

## 6. 실패 유형별 빠른 판단표

### A. 버튼 클릭 후 아무 일도 안 일어남

가능성:

- 개발 서버 미실행
- 클라이언트 에러
- `NEXTAUTH_URL` 문제

확인:

- 브라우저 개발자도구 콘솔 에러
- 터미널 에러 로그

### B. OAuth 화면까지는 가는데, 인증 후 우리 사이트로 안 돌아옴

가능성:

- 콜백 URL 미등록
- 콜백 URL 오타
- OAuth 콘솔의 도메인 설정 불일치

확인:

- 구글/네이버 개발자 콘솔의 Redirect URI
- 실제 복귀 URL이 무엇으로 찍히는지

### C. 우리 사이트로 돌아오지만 에러 페이지가 뜸

가능성:

- `NEXTAUTH_SECRET` 문제
- provider 설정 문제
- 세션 토큰 생성 문제

확인:

- 터미널의 NextAuth 로그
- 브라우저 URL의 `error` 파라미터

### D. `/register`로 돌아오는데 이름/이메일이 비어 있음

가능성:

- provider profile 매핑 문제
- 세션 콜백 문제
- OAuth 제공자에서 이메일 제공 동의 누락

확인:

- 로그인 후 세션 객체 확인
- 제공자 동의 항목에서 이메일 제공 여부 확인

### E. 로그인은 되지만 이후 권한 흐름이 이상함

가능성:

- `GUEST / USER / INSTRUCTOR / ADMIN` 역할 부여 흐름 문제
- GAS 사용자 조회와 OAuth 신규 사용자 흐름이 충돌

확인:

- `/register`에서 어떤 상태 문구가 나오는지
- 세션의 `role`, `provider`, `consentRequired` 값

## 7. 테스트할 때 꼭 기록할 것

실패하면 아래 5가지를 적어두면 원인 파악이 빨라진다.

1. 구글인지 네이버인지
2. 어느 단계에서 실패했는지
3. 주소창 URL이 무엇이었는지
4. 화면에 보인 에러 문구
5. 터미널에 찍힌 로그

## 8. 테스트 결과 판정

### 1차 합격

아래가 모두 되면 OAuth 기본 연결은 합격으로 본다.

- 구글 로그인 성공
- 네이버 로그인 성공
- 둘 다 `/register`로 복귀
- 이메일 자동 입력 확인

### 2차 합격

아래까지 되면 가입 흐름까지 연결된 것으로 본다.

- 소셜 로그인 후 가입 완료
- 다시 로그인 가능
- 세션 유지 확인

## 9. 테스트 후 바로 공유해주면 좋은 내용

대표가 테스트 후 아래처럼 간단히 주시면 바로 다음 수정을 이어갈 수 있다.

```text
구글: 성공 / 실패
네이버: 성공 / 실패
실패 단계: 예) 로그인 후 복귀는 되는데 /register에서 이메일이 비어 있음
에러 문구: 예) OAuthCallback
```

## 10. 다음 액션

- 둘 다 성공하면 다음 작업은 가입 완료 흐름과 권한 반영 검증이다.
- 둘 중 하나라도 실패하면 관리자 기능 추가보다 먼저 OAuth 문제를 해결한다.
