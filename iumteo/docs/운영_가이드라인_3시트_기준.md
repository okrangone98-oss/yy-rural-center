# 양양 이음터 운영 가이드라인

이 문서는 현재 운영 기준 문서입니다.
브랜드와 용어 기준은 [iumteo-brand-guideline-2026-03.md](./iumteo-brand-guideline-2026-03.md)를 우선합니다.

## 1. 운영 원칙

- 운영 기준 데이터는 3개의 Google Sheets 시트를 사용합니다.
- Google Sheets가 원본이며 Firestore는 미러링과 조회 최적화 용도로 사용합니다.
- 관리자 페이지, 문의 처리, 메일 발송, 채팅 상태는 모두 이 기준 문서를 따릅니다.

## 2. 기준 시트

1. `양양이음터강사DB`
   - 강사 기본 정보
   - 강사 상태
   - 공개용 강사 카드 정보
2. `이용자DB`
   - 일반회원 정보
   - 문의 회신용 연락 정보
3. `문의접수`
   - 문의 내역
   - 문의 상태
   - 강사 전달, 회신, 채팅 연동 기록

## 3. 사용하지 않는 구시트

- `users`
- `Lecturer_Profiles`

위 두 시트는 과거 구조로 간주하며 새 기능이나 운영 기준에 사용하지 않습니다.

## 4. 시트별 필수 항목

### 양양이음터강사DB

- 강사명
- 연락처
- 로그인용 이메일 또는 가입 이메일
- 상태

권장 항목

- 전문분야
- 활동지역
- 소개
- 프로필 사진
- isLocal

### 이용자DB

- 이름 또는 이용자명
- 연락처
- 이메일

권장 항목

- 소속
- 가입일시
- 마지막 활동일

### 문의접수

- 문의 대상 강사명
- 요청자 이름
- 요청자 연락처
- 요청자 이메일
- 문의 목적
- 처리 상태

권장 항목

- 접수일시
- 상세 내용
- 강사 전달일
- 회원 회신일
- chatRoomId
- chatRoomStatus

## 5. 로그인과 계정 원칙

- 일반회원과 강사님은 전화번호 또는 가입 이메일로 로그인할 수 있습니다.
- 관리자 계정은 별도 규칙으로 운영합니다.
- 강사님의 초기 비밀번호 정책은 현재 서비스 규칙에 따릅니다.
- 동일 이메일 중복 가입은 허용하지 않습니다.

## 6. 문의와 채팅 운영 흐름

1. 일반회원이 문의를 등록합니다.
2. `문의접수` 시트에 기록합니다.
3. 강사님에게 알림 메일 또는 관리자 전달이 진행됩니다.
4. 문의와 함께 채팅방이 생성되거나 연결됩니다.
5. 강사님이 수락하면 채팅 상태가 `ACTIVE`가 됩니다.
6. 협의가 끝나면 `ARCHIVED`로 종료합니다.

### 현재 정책

- 월 문의 제한: 20회
- 채팅 메시지 총 길이 제한: 300자
- `ARCHIVED` 상태 방은 `expireAt` 기준 TTL 삭제 대상

## 7. Firestore 미러링 원칙

- 원본은 Google Sheets입니다.
- Firestore는 다음 용도로 사용합니다.
  - 관리자 조회 성능 개선
  - 채팅방 상태 저장
  - 메일 발송 이력 보조
  - 실시간 UI 반영

### 주요 컬렉션

- `users`
- `lecturer_profiles`
- `inquiries`
- `chat_rooms`
- `mail_outbox`

## 8. 관리자 페이지 운영 포인트

- 회원, 강사, 문의를 탭 단위로 확인합니다.
- 문의 상태 변경과 강사 전달, 회원 회신을 한 화면에서 처리합니다.
- 데이터 무결성 경고를 우선적으로 확인합니다.
- 대량 작업보다 즉시 운영 대응 중심으로 사용합니다.

## 9. 필수 운영 체크

- Firebase Admin 환경변수가 정상인가
- SMTP 또는 Resend 메일 설정이 정상인가
- `chat_rooms.expireAt` TTL 정책이 등록되어 있는가
- 시트 공개 범위가 과도하게 열려 있지 않은가
- 문의와 채팅 상태가 시트와 Firestore에서 서로 어긋나지 않는가

## 10. 다음 유지보수 원칙

- 브랜드나 용어가 바뀌면 먼저 브랜드 가이드라인을 수정합니다.
- 운영 흐름이 바뀌면 이 문서를 갱신합니다.
- 새로운 문서를 만들기보다 이 두 기준 문서에 통합합니다.
