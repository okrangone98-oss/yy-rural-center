# 양양이음터 운영 가이드라인

## 목적

- 운영 원본 DB를 3개 Google Sheets로 고정합니다.
- 관리자, 강사, 일반회원, 문의 운영 흐름의 기준점을 문서로 남깁니다.
- Firestore 미러와 관리자 페이지는 이 문서를 기준으로 정렬합니다.

## 운영 원본 시트

1. `양양이음터강사DB`
   - 공개 강사 목록
   - 강사 승인 상태
   - 강사 프로필 운영 원본
2. `이용자DB`
   - 일반회원 가입 정보
   - 일반회원 연락처 및 문의 회신 대상 정보
3. `문의접수`
   - 강사 문의 접수 내역
   - 센터 검토 상태
   - 강사 전달 및 회원 회신 운영 이력의 기준

## 사용하지 않는 시트

- `users`
- `Lecturer_Profiles`

위 2개 시트는 과거 구조 또는 전환 잔재로 간주합니다. 신규 기능, 운영 기준, 무결성 점검 기준에서 제외합니다.

## 시트별 책임 범위

### `양양이음터강사DB`

- 한 행은 강사 1명을 의미해야 합니다.
- 로그인 및 식별 기준은 `로그인용 이메일` 또는 이에 준하는 이메일 컬럼 하나로 고정합니다.
- 필수값
  - `성명`
  - `연락처`
  - `로그인용 이메일`
  - `상태`
- 권장값
  - `전문분야`
  - `활동지역`
  - `소개`
  - `프로필사진`
  - `isLocal`

### `이용자DB`

- 한 행은 일반회원 1명을 의미해야 합니다.
- 이메일 기준으로 중복 가입을 허용하지 않습니다.
- 필수값
  - `이름` 또는 `이용자명`
  - `연락처`
  - `이메일`
- 권장값
  - `소속`
  - `가입일시`
  - `마케팅동의`

### `문의접수`

- 한 행은 문의 1건을 의미해야 합니다.
- 필수값
  - `문의대상(강사명)`
  - `신청인 성명`
  - `신청인 연락처`
  - `연락받을 이메일`
  - `문의 목적`
  - `처리 상태`
- 권장값
  - `접수일시`
  - `상세 내용`
  - `센터 전달일`
  - `강사 회신일`
  - `회원 회신일`

## 운영 규칙

1. 강사와 일반회원은 이메일 기준으로 각 시트 내 중복을 허용하지 않습니다.
2. 강사와 일반회원을 같은 이메일로 이중 등록하지 않는 것을 원칙으로 합니다.
3. 문의접수의 `문의대상(강사명)`은 반드시 `양양이음터강사DB`의 강사명과 일치해야 합니다.
4. 강사 상태값은 고정 집합으로 관리합니다.
   - `대기`
   - `승인`
   - `반려`
   - `비활성`
5. 문의 상태값도 고정 집합으로 관리합니다.
   - `접수대기`
   - `센터검토중`
   - `강사전달완료`
   - `강사답변도착`
   - `회원회신완료`
   - `종결`

## 운영 흐름

### 일반회원 가입

1. 가입 폼 제출
2. `이용자DB`에 신규 행 생성 또는 이메일 기준 중복 검사
3. Firestore 미러 `users`에 복제

### 강사 가입

1. 강사 가입 폼 제출
2. `양양이음터강사DB`에 신규 행 생성
3. 초기 상태는 `대기`
4. Firestore 미러 `users`, `lecturer_profiles`에 복제

### 강사 문의

1. 일반회원이 강사 문의 작성
2. `문의접수`에 저장
3. 센터가 검토
4. 센터가 강사 이메일로 전달
5. 강사 답변을 센터가 확인
6. 센터가 일반회원 이메일로 회신

## Firestore 미러 원칙

- 원본은 항상 Google Sheets입니다.
- Firestore는 조회 최적화, 관리자 검색, 메일 아웃박스, 향후 실시간 기능 보조용입니다.
- 미러 컬렉션 기준
  - `users`: `이용자DB` + `양양이음터강사DB`의 로그인 가능 사용자
  - `lecturer_profiles`: `양양이음터강사DB`
  - `inquiries`: `문의접수`
  - `mail_outbox`: 메일 발송 이력

## 관리자 페이지 기준

- 관리자 무결성 진단은 아래 4가지를 최소 점검합니다.
  - 강사DB 중복 이메일
  - 이용자DB 중복 이메일
  - 강사DB와 이용자DB 간 이메일 중복
  - 문의접수의 강사명 불일치 및 필수값 누락

## 반드시 알아야 할 내용

### 1. 현재 공개 CSV는 개인정보 위험이 큽니다

- `이용자DB`와 `문의접수`가 `pub?...output=csv` 형태로 공개되어 있으면 사실상 외부 공개 상태입니다.
- 일반회원 정보와 문의내역은 공개 CSV로 두면 안 됩니다.
- 운영상 반드시 바꿔야 합니다.
  - 공개용은 `양양이음터강사DB`만 허용
  - `이용자DB`, `문의접수`는 비공개 시트 + GAS API 경유 조회로 전환

### 2. 평문 비밀번호 저장은 중단해야 합니다

- 현재 구조에 평문 비밀번호 컬럼이 있으면 즉시 중단하는 것이 맞습니다.
- 최소한 해시 저장으로 바꾸고, 가능하면 소셜 로그인 중심으로 전환해야 합니다.

### 3. 컬럼명 표준화가 필요합니다

- 같은 의미의 컬럼이 시트마다 다르면 운영 오류가 반복됩니다.
- 최소 표준 컬럼은 아래처럼 맞추는 것이 좋습니다.
  - 이름: `성명` 또는 `이용자명`
  - 연락처: `연락처`
  - 이메일: `이메일`
  - 로그인 이메일: `로그인용 이메일`
  - 상태: `상태`
