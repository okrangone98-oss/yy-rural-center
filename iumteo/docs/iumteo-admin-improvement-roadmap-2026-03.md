# 양양이음터 관리자 모드 개선 로드맵

작성일: 2026-03-13

## 1. 목적

이 문서는 양양이음터 관리자 모드를 안정적으로 고도화하기 위한 기준 문서다.

핵심 원칙은 아래와 같다.

- 로그인 안정화가 최우선이다.
- 운영 중인 Google Sheets + GAS 구조를 갑자기 뒤집지 않는다.
- 기능 추가보다 운영 오류 감소와 검증 가능성을 먼저 확보한다.
- 정적 관리자 페이지와 Next 관리자 페이지를 장기적으로 하나의 운영 콘솔로 수렴한다.

## 2. 현재 판단한 현황

### 2.1 공개 홈페이지

- 메인 홈페이지는 소개, 주요사업, 강사 이음터, 공지, 갤러리, 문의, 영상까지 이미 운영 가능한 수준이다.
- 데이터는 주로 Google Sheets CSV 기반으로 연결되어 있다.

### 2.2 양양이음터 서비스

- `Next.js + NextAuth + GAS + Firestore 미러` 구조가 이미 들어와 있다.
- 회원가입, 로그인, 일반회원 마이페이지, 강사 마이페이지, 문의 접수, 관리자 대시보드가 구현되어 있다.
- 관리자 대시보드는 회원 관리, 강사 관리, 문의 운영, 시트 통합 조회, 미러 동기화까지 포함하고 있다.

### 2.3 가장 중요한 리스크

- 네이버/구글 로그인 검증이 아직 운영 신뢰 수준까지 확인되지 않았다.
- `admin.html`, `admin_iumteo.html`, `iumteo/_old_html`, `Next /admin`이 함께 있어 운영 기준 화면이 분산되어 있다.
- 테스트용 관리자 로그인과 평문 비밀번호 비교 흔적이 있어 보안 정리가 필요하다.
- 일부 화면은 공통 API 대신 직접 CSV를 읽고 있어 데이터 반영 기준이 완전히 통일되지는 않았다.

## 3. 최우선 우선순위

### Phase 0. 인증 안정화

이 단계가 끝나기 전에는 큰 기능 추가를 최소화한다.

목표:

- 네이버 로그인 정상 동작
- 구글 로그인 정상 동작
- 로그인 후 `/register` 복귀 정상 동작
- 세션 유지 정상 동작
- OAuth 실패 시 원인 구분 가능

완료 기준:

- 로컬에서 네이버/구글 로그인 버튼 테스트 완료
- 콜백 URL 설정 검증 완료
- `.env.local` 필수값 확인 완료
- 실패 시 에러 패턴 문서화 완료

이번 주 작업 원칙:

- 인증 관련 수정은 한 번에 하나만 한다.
- 수정 후 반드시 직접 브라우저 테스트를 한다.
- 로그인 문제가 남아 있으면 관리자 UI 신규 기능 작업은 중지한다.

## 4. 단계별 개선 로드맵

### Phase 1. 관리자 운영 콘솔 정리

목표:

- Next 기반 `/admin`을 운영 기준 화면으로 확정
- 기존 정적 관리자 페이지는 점진적으로 읽기 전용 또는 백업 용도로 전환
- 관리자 메뉴 구조를 실제 업무 단위로 재정렬

우선 작업:

- `회원 관리`
- `강사 승인/관리`
- `문의 운영함`
- `데이터 무결성 점검`
- `시트/미러 동기화`
- `운영 로그`

완료 기준:

- 관리자 화면 진입 경로가 하나로 정리됨
- 운영자가 어디서 무엇을 수정해야 하는지 헷갈리지 않음
- 관리자 페이지 QA 체크리스트를 실제로 돌릴 수 있음

### Phase 2. 문의/승인 운영 워크플로우 고도화

목표:

- 센터가 실제 업무를 처리하는 화면으로 발전

우선 작업:

- 승인 대기 전용 큐
- 반려 사유 입력
- 문의 상태별 필터 저장
- 담당자 메모
- 회신 템플릿
- 처리 이력 타임라인
- 일괄 상태 변경

완료 기준:

- 문의 1건 처리 흐름이 화면 안에서 끝남
- 강사 승인/반려 이력이 남음
- 운영자가 시트 원본을 직접 열어보는 빈도가 줄어듦

### Phase 3. 콘텐츠 운영 통합

목표:

- 이음터 관리자 모드에서 공개 홈페이지 핵심 콘텐츠까지 운영 가능하게 확장

우선 작업:

- 공지 노출 여부 관리
- 메인 팝업 on/off
- 추천 강사 또는 메인 노출 강사 설정
- 메인 영상/이미지 노출 순서 관리
- 연도별 주요사업 카드 편집 기준 정리

완료 기준:

- 홈페이지 운영을 위해 별도 정적 파일 수정이 거의 필요 없어짐
- 콘텐츠 변경이 시트 또는 관리자 화면 한 곳으로 수렴됨

### Phase 4. 보안 및 운영 안정성 강화

목표:

- 운영 투입 가능한 수준의 인증/권한/로그 체계 확보

우선 작업:

- 테스트용 `admin/admin` 제거
- 비밀번호 평문 비교 제거 또는 최소한 해시 기반 구조로 전환
- 관리자 액션 로그 기록
- 실패 알림 표준화
- 환경변수 문서 정리

완료 기준:

- 관리자 계정 임시 우회 경로 제거
- 누가 무엇을 바꿨는지 추적 가능
- 인증 실패와 권한 실패를 구분할 수 있음

### Phase 5. 데이터 일관성 통합

목표:

- 화면별 데이터 소스를 통일

우선 작업:

- 강사 상세 페이지의 직접 CSV 접근을 공통 API 기반으로 변경
- 공개 화면과 관리자 화면의 상태값 정의 통일
- 시트, GAS, Firestore 미러 간 반영 순서 문서화

완료 기준:

- 관리자에서 바꾼 값이 사용자 화면에 일관되게 반영됨
- 어디가 원본이고 어디가 미러인지 팀이 명확히 이해함

## 5. 실제 작업 순서 제안

작업은 아래 순서로 진행한다.

1. 네이버/구글 로그인 직접 테스트 문서 기준으로 로컬 검증
2. OAuth 실패 원인 정리 및 수정
3. 관리자 기준 화면을 `Next /admin`으로 확정
4. 관리자 승인/문의 워크플로우 UX 개선
5. 보안 정리
6. 콘텐츠 운영 통합
7. 데이터 소스 통합

## 6. 우리 작업 방식

오류를 줄이기 위해 아래 방식으로 같이 작업한다.

- 한 번에 한 주제만 수정한다.
- 매 작업마다 `목표 / 수정 파일 / 테스트 방법 / 기대 결과`를 먼저 짧게 정한다.
- 인증 관련 수정 후에는 코드 설명보다 직접 테스트를 먼저 한다.
- 테스트 성공 전에는 다음 단계 기능 추가로 넘어가지 않는다.
- 운영에 영향이 큰 변경은 문서와 코드 둘 다 같이 갱신한다.

## 7. 다음 즉시 실행 항목

지금 바로 시작할 일은 아래 두 가지다.

1. 네이버/구글 로그인 직접 테스트를 대표가 브라우저에서 실행한다.
2. 테스트 결과를 기준으로 OAuth 설정 또는 코드 문제를 좁힌다.

이 문서 기준으로 당분간은 Phase 0을 최우선으로 본다.
